# 抖音标记视频自动跳过（30x16/购物）

在 `https://www.douyin.com/?recommend=1` 里，**当前正在播的这一条**视频一旦出现下面任一标记，
立刻切换到下一个视频：

```html
<rect width="30" height="16" rx="2">            <!-- 标记一 -->
<div class="gwmKU4Jo">购物</div>                <!-- 标记二：class 是 gwmKU4Jo 且含「购物」 -->
```

选择器就是 `rect[width="30"][height="16"][rx="2"]` 和 `div.gwmKU4Jo`（+ 文本含「购物」）——
老师贴的 DOM，原样照用，没有加别的猜测。

## 判定规则

三个条件同时成立才算「命中当前视频」：

1. **可见** —— 元素的 `getBoundingClientRect()` 与视口相交（宽高都要 ≥2px）
2. **属于活跃卡片** —— `el.closest('[data-e2e="feed-item"]') === [data-e2e="feed-active-video"]` 所在的卡片
   （找不到归属、或页面没自报活跃卡片时不卡这条，交给第 1 条）
3. **这条视频还没处理过** —— 按 `data-e2e-vid` 去重，只有确认跳走了才记账

第 2 条是关键：推荐流会**预加载下一张卡片**，那张卡片里也有同样的标记，
但它不在当前这条视频上，不该触发跳转。对「购物标签」尤其重要——标签只在卡片里，
必须认卡片归属。

第二种标记额外要求 `textContent` 里含「购物」：同名的 `div.gwmKU4Jo` 里如果写的是
「视频同款」之类，不算命中（离线用例 `div-nocart` 专门测这个）。

## 跳转方式（沿用带货插件里实测有效的两招，都有校验）

1. 点页面自己的「下一条」箭头（`[data-e2e="video-switch-next-arrow"]` 等）——最接近原生滑动，也最快
2. 视频没换 → 把滚动容器 `.slidelist` **精确推一条**（对齐下一条卡片的真实偏移）

刻意不做：`scrollIntoView`、`window.scrollBy`、连环多次滚动——这三样会让推荐流一片黑。
跳完如果画面上一条卡片都没有，会自动回滚一条把内容找回来（空白自救）。

## 「跳过之后卡住」的修复（v1.1.1）

老师反馈：带标记的视频确实被跳过了，**但画面卡住，要手动按「恢复画面」**。三条成因，逐条修：

| # | 成因 | 修法 |
|---|---|---|
| ① | **程序化换页让抖音播放器停在 00:00**（看起来就是卡住） | 换页后给滚动容器补发合成的 `scroll` 事件，并对「暂停中或还在 00:00」的视频显式 `play()`；分 **350 / 1000 / 1800 ms** 三次做，因为刚换页时播放器常常还没挂上新的视频源 |
| ② | **停在两条卡片的边界上**，页面会当成没翻页 | 兜底多推 **4px**；跳完 2.5 秒内持续检查，偏了就把当前卡片对齐回容器顶部（`alignActive`，只在偏得不超过 0.6 屏时修） |
| ③ | **箭头和滚动各推了一次**（页面换页是异步的，确认太早就会重复推） | 箭头点完最多确认三次（500 / 800 / 1100 ms），确认换了页就绝不再推滚动容器 |

## 触发速度与安全阀

| 参数 | 值 | 说明 |
|---|---|---|
| 检测节拍 | 250 ms | 兜底轮询 |
| DOM 变动重检 | 120 ms 节流 | MutationObserver，让「立刻」不依赖节拍 |
| 两次跳转最小间隔 | 600 ms | 老师要求「立刻」，所以很短 |
| 触发后冷却 | 600 ms | 同上 |
| 安全阀 | 10 秒最多 3 次 | 超出暂停 20 秒并提示 |
| 连败保护 | 连续 3 次没跳成功 | 暂停 30 秒并提示 |

实测（离线用例）：从页面出现标记到完成跳转约 **130 ms**。

## 安装/更新

```
chrome://extensions  →  右上角打开「开发者模式」  →  「加载未打包的扩展程序」→ 选中本目录
```

已经装过的：改完代码后在本插件卡片上点**「重新加载」**即可；卡片上的版本号会从
1.0.0 变成 1.1.0，那就是重载真的生效的证据。装好/重载后要**刷新一次抖音页面**
（内容脚本只在页面加载时注入）。

## 弹窗

- **启用** 开关
- **今日已跳过 / 累计** 计数
- **当前视频上的标记** —— 出现 / 未出现
- **立即检查一次** —— 强制检查并立即执行一次（不受冷却限制）；没命中时会列出页面上
  找到的每个标记以及它是否属于当前这条
- **恢复画面** —— 画面卡住或黑屏时，把推荐流滚回来一条
- **清空计数** —— 计数归零，并清掉「已处理视频」名单
- 快捷键 **Ctrl+Shift+Z** = 恢复画面（刻意避开带货插件的 Ctrl+Z，免得抢键）

## 离线用例（test/mock.html）

不用登录抖音也能验证逻辑，七个用例（`mock.html` 里给了每张卡片一个「停在 00:00 的 video」，
所以还能验证播放救援有没有真的发生）：

| 用例 | 构造 | 期望 | 实测（v1.1.1） |
|---|---|---|---|
| `?case=active` | rect 标记在当前这条视频上 | 立刻跳走，只跳一条，且救回播放 | ✅ 128 ms → 1002，play ×3，补发 scroll ×3，对齐 |
| `?case=other` | rect 标记在**可见但不活跃**的卡片上 | 不跳 | ✅ 不跳，play ×0 |
| `?case=offscreen` | rect 标记只在视口外那一条上 | 不跳 | ✅ 不跳 |
| `?case=div-active` | `div.gwmKU4Jo`+「购物」在当前这条上 | 立刻跳走 + 救回播放 | ✅ 129 ms → 1002，play ×3 |
| `?case=div-other` | 购物标签在可见但不活跃的卡片上 | 不跳 | ✅ 不跳 |
| `?case=div-nocart` | `div.gwmKU4Jo` 但文字是「视频同款」 | 不跳 | ✅ 不跳 |
| `?case=misalign` | 换页后**故意少滚 40px**（停在两条之间） | 自动对齐到卡片边界 | ✅ scrollTop 修正回 604（= 卡片真实偏移） |

用浏览器直接打开 `test/mock.html?case=misalign` 即可复跑。

## 注意：可能和「抖音带货视频自动跳过」撞车

带货插件（`../douyin-shop-skip`）用的是 `svg[width="30"][height="16"]` 和
`div.gwmKU4Jo`+「购物」——这两个标记本插件现在也都认。
两个插件同时开着，同一条视频会被各跳一次，等于**一次跳过两条**。真出现就关掉其中一个
（两边弹窗都有「启用」开关）。
